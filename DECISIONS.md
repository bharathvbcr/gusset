# Decisions

Append-only. An agent does not reopen a decided item without a new entry here.

| Date | Decision | Choice | Why | Rejected |
| --- | --- | --- | --- | --- |
| 2026-09-20 | Allocator | Gusset declares no `#[global_allocator]`. It ships `gusset::alloc::Counting<A>`, a wrapper the app installs around whatever allocator it already uses, plus `gusset_alloc_stats()` exporting live bytes and peak | Only one global allocator per binary; a framework that claims it cannot be adopted by apps that already picked mimalloc or jemalloc | `mimalloc` feature flag (kept only in the example engine) |
| 2026-09-20 | Completion wakeup | Go creates the pipe with `os.Pipe()` and hands the write fd to `gusset_handle_open`; a worker writes the 8-byte ticket id when a job finishes; the reader goroutine parks on the netpoller. Windows v0.1 uses the blocking call under the semaphore | `os.Pipe` is pollable with no runtime internals; writes of at most `PIPE_BUF` bytes are atomic; bounded in-flight means the pipe never fills | `eventfd` (counter, no ticket ids), kqueue user events (macOS-only), Go callbacks from Rust threads |
| 2026-09-20 | License | `MIT OR Apache-2.0` | Rust ecosystem default, superset of the Apache-2.0 used by sparsl and tessl | Apache-2.0 alone |
| 2026-09-20 | Out-of-process (Phase 4) | Contribute the Go binding upstream to iceoryx2; `gusset-ipc` is a thin adapter, not a transport | Distribution and maintenance from an existing project | Standalone shm bus |
| 2026-09-20 | Version floor | Latest-minus-one for Go and Rust, bumped on a schedule | Develop on latest and nightly; adopters lag by one release at most | Fixed MSRV years back |
| 2026-09-20 | Input ownership | Inputs up to 4 KiB copied during `gusset_submit`; larger inputs in Rust-owned `Buffer`s filled by Go | Submit-and-return plus `#cgo noescape` forbids Rust touching Go memory after the call returns | Pinning Go memory for the job's lifetime |
| 2026-09-20 | Cancellation | Per-job `AtomicBool` in Rust memory, set by `gusset_cancel(handle, ticket)`; `gusset_cancel_all` on `Close` | Rust may never read a Go-owned atomic; per-job matches `context.Context` semantics | Generation counter on the Go handle; absolute deadlines |
| 2026-09-20 | Clock domain | Header carries relative `timeout_ns` computed at submit | Go's monotonic reading is process-internal and macOS/Linux sources differ from Rust `Instant` | Absolute `deadline_ns` |
| 2026-09-20 | Worker pool scope | One pool per handle, sized at `gusset_handle_open` | Engines differ in parallelism; per-handle keeps the semaphore and pool the same size | Process-global pool |
| 2026-09-20 | ABI surface | 14 exports, three `#[repr(C)]` types, one `gusset_abi_layout()` for version/size/align | Small enough to list in `exports.txt` and diff against `nm` | Per-type `gusset_sizeof_*` functions |
| 2026-09-20 | Engine resolution | No registered engine means every submission is refused. The built-in diagnostic engine runs only when the caller sets `GUSSET_FLAG_DIAGNOSTIC_ENGINE` (`gusset.WithDiagnosticEngine()`), and a registered engine always outranks that flag | The diagnostic engine selects behaviour from `input[0]`, and bytes 1/2/3 are panics. As the implicit default it let an untrusted payload's first byte choose a Rust panic and poison the handle. Registration is a Rust-only API with no C export, so "nobody registered yet" is a reachable production state, not a hypothetical | Deleting the diagnostic modes (the panic zoo and pitfall suite need them); a cargo feature (produces two different `libgusset.a` from one `make`, and the wrong one ships) |
| 2026-09-20 | ABI version 2 | `AbiLayout` covers four `#[repr(C)]` types — `CallHeader`, `FfiStatus`, `AbiLayout`, `AllocStats` — and `sizes`/`aligns` grew to `[u32; 4]`, taking `AbiLayout` from 28 to 36 bytes. Go additionally cross-checks Rust's reported layout against what cgo compiled | `gusset_alloc_stats` writes `AllocStats` straight into Go memory and version 1 verified nothing about it, so a size or alignment disagreement corrupted the Go heap unnoticed. `internal/ffi/gusset.h` is hand-maintained, not generated by cbindgen, so the runtime check is the only guard against header drift | Leaving `AllocStats` unverified; generating the header in `build.rs` (a larger change, still worth doing) |
| 2026-09-20 | Pool size ceiling | `MAX_POOL_SIZE = 1024`, and a larger request is refused rather than clamped | Each worker is an OS thread with an 8 MiB stack, so the argument was an unbounded thread and address-space request. It also keeps unread completion tickets under 8 KiB, which every supported platform's pipe buffer holds — that is what makes a full pipe unreachable under the bounded-concurrency contract. Clamping silently would leave the caller with the wrong capacity model | Silent clamp; no bound |
| 2026-09-20 | Ticket ownership | A ticket has exactly one waiter. `Wait` on an unknown ticket returns `ErrUnknownTicket`; a second concurrent `Wait` returns `ErrTicketBusy` | Both cases previously parked the caller forever and ignored its context deadline: an unknown ticket waited for a completion that was never coming, and a second `Wait` displaced the first waiter's channel so the first could never be woken. A result can be moved out once, so it can have one waiter | Bounding the post-cancel drain instead (releases the semaphore permit while the job still runs, breaking I4) |
| 2026-09-20 | Linking modes | Default `#cgo LDFLAGS` keep resolving this checkout's `target/`; adopters use `-tags gusset_pkgconfig` with the installed `gusset.pc`, or `CGO_LDFLAGS=-L…`. An umbrella crate must set `[lib] name = "gusset"` | `target/` is gitignored, so it is absent from the module zip and the module cache — an external module got `ld: library 'gusset' not found` and could not build at all. cgo links `-lgusset`, so the umbrella's *output* name is the constraint, not its package name | Shipping a prebuilt archive in the module (one per platform); making pkg-config the default (breaks the in-repo build) |
| 2026-09-20 | LTO | `lto` is the adopter's choice, not part of the contract. Gusset's own release profile keeps `fat`; the checklist no longer prescribes it | No invariant depends on it, and a real adopter (DevCouncil) had already measured `thin` as the better trade for its workspace. A `fat` archive is LLVM bitcode that a system `nm` cannot read, which is what hid the export check never inspecting the shipped archive | Mandating `fat`; mandating `thin` |
| 2026-09-20 | Header verification | `internal/ffi/gusset.h` stays hand-maintained. `tests/header_match.rs` parses both sides and compares **parameter and return types**, not just names. `cbindgen.toml` was deleted | The checklist claimed the header was "generated by `build.rs`, committed, and diffed in CI" and had been checked off; `build.rs` only enforces `panic = "unwind"` and has never run cbindgen. The stray config made the claim look plausible, so it was evidence for a process that does not exist. Type-level comparison gives the property cbindgen would have — a widened parameter, a dropped `const`, a removed argument — with no build-dependency | Wiring cbindgen into `build.rs` (adds a build-dependency; still open); leaving the config in place as intent (indistinguishable from a working generator) |
| 2026-09-20 | Supported platforms | Unix only, enforced by a `compile_error!` in `lib.rs`. `make cross` compile-checks linux-gnu, linux-musl and darwin; CI asserts Windows *fails* with that error | The matrix named a cross job covering `windows/amd64-gnu` and no cross leg existed, so "the Windows completion path is untested" understated it — it cannot work. The completion path is a POSIX pipe, I5 is `sigaltstack`, stack accounting is pthread, and `gusset_handle_open` takes an `int32` fd where a Windows handle is pointer-sized. Failing with a named error beats failing inside `pool::sys` with a `libc` symbol cascade | Claiming Windows support; silently letting the build fail deep in `sys` |
| 2026-09-20 | Fuzzing | Go native fuzzing over the FFI boundary, in the matrix rather than nightly | `cargo fuzz` would have meant adding `libfuzzer-sys` and a nightly-only build for a repository that is otherwise stable-only. Go's fuzzer needs no dependency and points at the boundary where untrusted bytes actually enter. It costs about two minutes, so it runs per-PR instead of nightly, where a crasher would sit undiscovered for a day | `cargo fuzz` (new dependency); leaving `fuzz` unimplemented |
| 2026-09-20 | R4 static enforcement | `gussetvet` owns the `C.free` check; the CI forbidden-pattern audit no longer duplicates it | Two enforcers for one rule, and the cruder one fired on the stricter one's source: a blanket `grep -F` cannot tell a call from a comment describing the rule, which is the same failure that made the lint job red on every commit by matching `AGENTS.md`. `gussetvet` strips comments, carries an explicit allowlist for the one package holding the deliberate violation, and reports file:line | Keeping both (the audit fails on `gussetvet`'s own comments); allowlisting `gussetvet` from its own rule (hides a genuine violation if it ever grows a cgo call) |
| 2026-09-20 | Zero-Copy Egress & Opcode Dispatch | `(*Handle).WaitBuffer` returns a zero-copy Rust-owned `*Buffer` with GC `AddCleanup` backstop; `WithOpcode`/`ContextWithOpcode` passes engine opcode in `CallHeader.reserved` | Return path for large outputs previously suffered two copies (Rust Vec -> C FFI -> Go slice). `WaitBuffer` eliminates both copies. Multi-engine routing enables multiplexing multiple engines on a single handle without payload byte-mangling | Separate multiplexer proxy; returning raw pointers to Go callers |
| 2026-09-20 | Non-Blocking Pipe Enforcement & Pipeline Unification | `Handle::open` and Go `Open` enforce `O_NONBLOCK` on `pipe_write_fd`; `s.call` delegates to `s.submit` + `s.wait`; defensive buffer boundary validation | Prevents kernel blocking on full pipe that rendered `WRITE_TICKET_TIMEOUT` dead code; eliminates ~90 lines of duplicate lifecycle logic in `s.call`; prevents nil/freed/cross-handle buffer panics | Allowing caller to control pipe blocking state; maintaining separate call loop |
| 2026-09-20 | Concurrency & Boundary Hardening | Extended `s.cgoMu.RLock()` across `semTickets` insertion; post-semaphore poison fast-fail; nil receiver safety across Handle/Buffer; `Ordering::Acquire` on cancel flag; 63-bit buffer id overflow ceiling | Eliminates submit/close race where closing handle drained permits before newly submitted ticket registered; prevents entering Rust on poisoned handle (R10); eliminates unhandled nil pointer panics; ensures strict hardware memory synchronization for cancellation | Leaving submit/close window unsynchronized; panicking on nil receivers |
| 2026-09-20 | `WithPoolSize` range is checked in `int` | `n < 1` or `n > MaxPoolSize` is refused before the `uint32` conversion. `WithPoolSize(0)` is no longer a silent default-4 | `uint32(n)` turned `1<<40` into a 0-capacity Go semaphore (every `Call` hung until the context died) and `1<<32+4` into a 4-worker pool | Treating 0 as "use default" on the Go option (the Rust C API still maps 0 to `DEFAULT_POOL_SIZE`) |
| 2026-09-20 | Permit ownership, take-buffer egress, nil context | `waitInternal` releases the semaphore only after it owns the wait; `submit` inserts a cancel flag only while the sender is live; `drainPipe` keeps take()'s buffer id in a side map until a waiter consumes it (`WaitBuffer` wraps, `Wait` copies and frees); nil `context.Context` is rejected rather than panicking; `close` holds the workers mutex across join | `ErrTicketBusy` had been returning the owner's permit (I4); a failed send leaked `in_flight`; `WaitBuffer` of a 64 KiB `JobResult::Ok` still did a Go copy; wrapping that buffer in `drainPipe` taxed `Wait` (6 allocs/op vs 3); putting the id on `callResult` grew every Call by 10% B/op. A nil context aborted the calling goroutine. Small `Call` stays on the inline copy path so the noop is not taxed a Buffer wrapper | Bounding the post-cancel drain (already rejected); wrapping every take buffer (measured +2 allocs/op on `Call`); wrapping large take buffers in `drainPipe` (measured +3 allocs/op on `Wait`); a uint64 on `callResult` (measured +10% B/op on CallParallel) |
| 2026-09-20 | Buffer size ceiling | `MAX_BUFFER_BYTES = 1 << 30` (1 GiB), refused rather than clamped, on both `NewBuffer` and `RawBuffer::allocate` | A production `int` fed straight into `posix_memalign` is an unbounded address-space request. 1 GiB is above the 200 MiB memlimit assertion and the 64 KiB egress benches; anything larger belongs in Phase 4 isolation | Silent clamp; matching `GOMEMLIMIT` (that is a process budget, not a per-buffer cap) |
| 2026-09-20 | Instant overflow is expiry, not infinity | `resolve_deadline` maps a non-zero `timeout_ns` whose `checked_add` overflows to the submit instant (already expired), never to `None` | `None` already means "no deadline" for `timeout_ns == 0`. Treating overflow the same way made `u64::MAX` nanoseconds run forever, which is the opposite of I3 | Saturating to `Instant::MAX` (not portable across clock epochs); refusing the submit (changes the public timeout contract) |
| 2026-09-20 | Large `Ok` results promote on the worker | After dispatch, `JobResult::Ok` larger than 4 KiB is copied into a `Buffer` on the worker thread; `gusset_take` then returns the id with the high bit set | The take-side memcpy pinned an M for the copy of every large diagnostic echo and every adopter `Vec<u8>` egress. Promotion keeps the cgo call under the ~20 µs P-handoff threshold (R16, I4) | Copying in `gusset_take` (the previous path); adding a 15th export for "take without copy" |
| 2026-09-20 | `WaitBuffer` wrap holds `cgoMu` | `waitBuffer` installs the take view under `cgoMu.RLock` and returns an error if the handle is already closed | `Wait` already copied under that lock after a torn first cache line under `GOGC=1`. `WaitBuffer` wrapping after `waitInternal` returned left a window `HandleClose` could win, and the 3-byte close-race never exercised it | Copying every large `WaitBuffer` onto the Go heap (defeats R16); wrapping in `drainPipe` (already measured +3 allocs/op on `Wait`) |
| 2026-09-20 | A deadline bounds the caller, not the work | On `ctx.Done` the waiter cancels best-effort, detaches, and returns `ctx.Err()` immediately. The ticket goes into an `abandoned` set; `drainPipe.deliver` discards the result, frees any take buffer and returns the permit when the completion lands. The permit is **not** released at detach time | The previous unconditional `<-ticketCh` made the deadline a statement about the engine rather than about Gusset — measured, 80 ms deadline, 1.503 s return — because cancellation is cooperative and no real adopter engine calls `JobContext::check`. Releasing the permit at detach would be the opposite error: the worker is still executing, so a further submission would put in-flight work above the pool size, fill Rust's `pool_size * 2` channel, and block `gusset_submit` inside cgo (I4/R11). The permit models "a worker is busy", which is still true | Bounding the drain with a timer (same I4 breach, just later); preemptive cancellation (needs a signal into an arbitrary adopter engine — that is Phase 4 process isolation, not in-process); leaving it and documenting the deadline as advisory |
| 2026-09-20 | Abandoned tickets are spent | `Wait` on an abandoned ticket returns `ErrUnknownTicket` | The result is already promised to the bin, so a second waiter could only park for a completion it will never be handed — the same forever-park the detach exists to remove | Letting a re-`Wait` re-attach (two owners for one move-once result); keeping the ticket waitable until close (parks indefinitely) |
| 2026-09-20 | Bounded shutdown is `Shutdown`; `Close` stays a join | `gusset.Shutdown(drain)` exports the existing budgeted Rust drain. `Handle.Close` keeps joining its workers with no budget | Rust had implemented the budgeted drain, Rust tested it, `internal/ffi` bound it and the README advertised it, and no exported Go function called it — the one bounded shutdown Gusset offers was unreachable by the audience it is for. `Close` must stay a join: detaching workers would leave OS threads running against Rust memory that `HandleClose` is about to free. The pair is the contract — `Shutdown` with a budget, then `Close`, whose join is then short because the cancel already landed | Adding a timeout to `Close` (leaks threads into freed memory); leaving `Shutdown` unexported (the README already promised it) |
| 2026-09-20 | `CallBuffer`, not `Call(ctx, any)` | Added `(*Handle).CallBuffer(ctx, *Buffer) (*Buffer, error)`; `Call` keeps its `[]byte` signature | `Call` refuses `[]byte` over 4 KiB, so the payload sizes zero-copy exists for were the ones the one-line API rejected, and every adopter hand-rolled `Submit` + `WaitBuffer` — including the `KeepAlive` that stops the input's `AddCleanup` freeing Rust memory mid-call. Widening `Call` to `any` would have matched `Submit`'s shape but turned a compile error into a runtime one, against the house rule to narrow rather than reach for an escape hatch | `Call(ctx, any)` (loses the type check on the hot path); leaving adopters to compose it (the `KeepAlive` is not discoverable) |
| 2026-09-20 | An engine may not return its input as its output | The worker refuses `JobOutput::Buffer(id)` when `id` is the unit's `input_buffer_id`, or 0, converting it to `JobResult::Err`. `WorkUnit` carries the input id for this | Go frees a take buffer after copying the result out of it, so returning the input id released a `*Buffer` the caller still owned and left the slice it had already been handed pointing at freed pages — a use-after-free an adopter opens by writing the obvious echo. A test asserting Gusset's own echo does not alias covered one engine, not the contract | Documenting it as an engine-author rule (the failure is silent memory corruption, not a wrong answer); checking it in `gusset_take` (too late — the id is already the result, and take cannot tell which buffer was the input) |
| 2026-09-20 | Timing assertions are relative to the engine | The detach tests bound the caller against `engineRuns/2` rather than an absolute millisecond figure | The contract is "the caller returns before the engine does", and the pre-fix code returned *after* the whole engine, so a relative bound cannot pass by luck. An absolute 500 ms bound tested the same property but failed under the parallel-package contention of `go test ./...`, which makes a real regression indistinguishable from a busy machine | Absolute bounds (flaky under load); no timing bound at all (the bug is entirely a timing bug — `errors.Is(err, DeadlineExceeded)` is true both before and after the fix) |
| 2026-09-20 | Crossover benchmarks measure transport, in isolated processes | `rs_spin` and diagnostic mode 11 run a byte-identical loop; `make bench-crossover` runs each transport in its own process at `-count=1` and writes to `bench/results/crossover/` | A noop benchmark measures the case where any coordination layer looks worst and which no adopter has; the useful number is the work duration at which coordination stops mattering, and that needs both transports turning one dial. Isolation is not hygiene but the measurement: Go never destroys an M, so sharing a process lets the second transport inherit the first's ~200 threads, and `-count>1` makes every later repetition read a delta against threads its own predecessor made. Both contaminations report that nothing happened | `RunParallel` for thread pressure (caps concurrency at `GOMAXPROCS`, so blocking cgo never has to grow the pool and `Δthreads` reads 0); a second `.txt` in `bench/results/` (`benchdoc` refuses to guess which platform the README describes) |
| 2026-09-20 | iceoryx2's Go binding is unstarted work, not integration work | Phase 4 stays specified, and this records why its first task is larger than "adapt the binding": as of iceoryx2 v0.10.0 (checked 2026-09-20) the upstream bindings are C, C++, Rust, Python and C#, with Go still listed as planned | The Phase 4 row above commits to *contributing* the Go binding upstream. An adopter reading "thin adapter over iceoryx2" could reasonably assume a binding exists to adapt. It does not, so Phase 4 begins with writing and upstreaming one — a different size of commitment, and one gated on a maintainer's review rather than on us alone | Recording it only in `docs/ipc.md` and `docs/why.md`, where a reader looking for the decision would not find it |
| 2026-09-20 | `make bench-scaling` exists | A target running `BenchmarkThreadScaling` one transport per process at `-count=1`, writing `bench/results/crossover/scaling-{rawcgo,gusset}-*.txt` | `tools/benchplot` requires those two files and named `make bench-scaling` in three of its error messages while no such target existed. The committed chart data therefore had no documented way to be regenerated, and the process isolation its validity depends on was enforced by nothing | Folding it into `bench-crossover` (different benchtime, different shape, and that target is already four arms long) |
| 2026-09-20 | Charts are gated like the numbers | `make docs` runs `tools/benchplot` and `make docs-check` runs it with `-check`, alongside `benchdoc`; `README.md` embeds the three charts | `benchplot` shipped a `-check` staleness flag that no target and no CI job invoked, and `docs/img/*.svg` were referenced by no document. The committed `crossover.svg` was drawn from transport samples taken before per-arm process isolation landed, so the published chart showed a curve its own data no longer supported. A generated artifact that nothing regenerates and nothing checks is a claim, not a measurement | Deleting the charts; leaving regeneration to whoever remembers |
| 2026-09-20 | A thread count that cannot be attributed is withheld, not printed | `reportPeakThreads` publishes `peakDthreads` always, and the absolute `peakThreads` only for the first transport to sample threads in that process; a second transport gets a log line naming the cause | Go never destroys an M, so a second transport inherits every thread the first created and its absolute peak is the predecessor's high-water mark. Run in one process, both transports reported an identical figure at every concurrency level — two flat, equal lines, which reads as "cgo is fine" from data that measured nothing. A missing metric fails benchplot loudly; a wrong one becomes a chart | Reporting it with a caveat in the doc comment, which the benchmark output does not carry |
| 2026-09-21 | Go tip bootstraps from the matrix pin | The weekly job installs Go `1.27.x` with `actions/setup-go` and sets `GOROOT_BOOTSTRAP` to that tree before `./make.bash`. A shell check refuses a resolved toolchain older than Go 1.26. Later steps set `GOROOT` to the tip tree and `GOTOOLCHAIN=local` | Run 35594759554 died building `cmd/dist` with the runner's Go 1.24.13: `found packages main (build.go) and building_Go_requires_Go_1_26_0_or_later (notgo126.go)`. Tip (1.28) requires a bootstrap >= Go 1.26.0. That is the compiler that *builds* tip, not Gusset's `go 1.26` floor | `./make.bash` against whatever `go` the runner image ships; raising `go.mod` to follow tip |
| 2026-09-22 | Poison refuses new work, not finished work | A result that exists when the handle is poisoned is delivered. `gusset_take` copies small results through the internal egress path, which checks only `closed`; `gusset_buf_alloc`, `NewBuffer` and every submission still refuse a poisoned handle | The poison-checked allocation turned a sibling's panic into a lost result for outputs of 4 KiB or less and a delivered one above it — an outcome decided by output size — and mislabelled it `FFI_ERR` rather than `ErrPoisoned` | Failing every in-flight result on poison: discards completed work and still needs the size inconsistency fixed |
| 2026-09-22 | One output owner per buffer | A buffer may become a job's output once per lifetime, and not while another work unit holds it as input. The claim is a flag on the registry slot, set under the registry lock; promoted egress buffers are born claimed | Go frees an output buffer after its waiter is done. Two results naming one buffer free it under each other, and an engine returning a captured pre-allocated id does that on its second call | Re-keying the buffer to a fresh id on return: changes the id an adopter host allocated and still leaves a Go-held idle buffer unprotected. That case — an engine returning a buffer Go allocated with `NewBuffer` and still holds — is not detectable without an ownership field on `gusset_buf_alloc` and remains open |
| 2026-09-22 | A published buffer is not an output | `gusset_buf_alloc` sets `caller_held` on the slot. `claim_output` refuses that id. `Handle::buf_alloc` stays unmarked, so an engine may still return a buffer it allocated itself, once | The open case above. Rust cannot see the Go `*Buffer`, so the fact of publication has to be recorded at the alloc that handed the pointer over. Refusing the move is the linear-type rule: the caller is still an owner, and the result path frees what it is given | Re-keying (rejected the same day); treating every `buf_alloc` as caller-held (forbids the engine-private buffer the once-per-lifetime rule exists to allow) |
| 2026-09-22 | Named field offsets are their own export | `gusset_abi_fields(offsets, sizes, cap)` returns the field count and writes at most `cap` entries. Go `init()` compares that table with `unsafe.Offsetof` / `unsafe.Sizeof` on the cgo structs. `AbiLayout` stays 36 bytes and ABI version stays 2. The surface is 15 exports | Whole-struct size and alignment do not change when equal-width fields trade places (`flags`/`reserved`, `span_id`/`timeout_ns`, any permutation of `AllocStats`). Version 2's check accepted that header, and the next struct write then read every swapped field from the wrong slot. Asking each compiler for the named offset is the check that sees it. Growing `AbiLayout` in place would write past the 36 bytes a version-2 caller allocated, before the version word could be checked | Appending the table to `AbiLayout` (stack smash on the previous caller); one `gusset_offsetof_*` export per field (the per-type sizeof option rejected 2026-09-20) |
| 2026-09-22 | Engine handlers dispatch outside registry lock | `EngineFn` is `Arc<dyn ...>`; `default_dispatch` clones the handler under the read lock and invokes it after releasing the lock | Holding `ENGINE_REGISTRY.read()` across engine execution allowed concurrent `register_engine` calls (which acquire write locks) to block future readers behind the pending writer on POSIX `RwLock`, stalling worker threads during long-running work units | Holding the read lock across execution; per-handle copy of the registry |
| 2026-09-24 | Stable `Allocator` trait (Rust 1.100) | `gusset::BufferAlloc` implements `std::alloc::Allocator`. It allocates 64-byte aligned blocks through `Global` and counts each byte exactly once. An engine returns `Vec<u8, BufferAlloc>` as `JobOutput::Allocated`, and the worker adopts that allocation as the result buffer without copying it. `Counting<A>` also implements `Allocator` for per-collection accounting; wrapping `Global` while `Counting` is the global allocator is detected and not counted twice. A build-script probe enables all of this per compiler (`cfg(gusset_allocator_api)`), and `rust-version` stays 1.97 | A `Vec<u8>` result above 4 KiB was copied into a buffer on the worker, which doubled peak memory for large outputs. It could not be adopted because its memory is not 64-byte aligned and it was allocated with a different layout. Building the output in buffer memory from the first byte keeps the alignment promise and removes the copy. Probing rather than comparing versions gets the right answer on nightlies and vendor toolchains, and `GUSSET_ALLOCATOR_API=1` lets a CI lane fail instead of falling back silently | A cargo feature (it breaks the build on older compilers, and one `make` would produce two different archives again); raising `rust-version` to 1.100 (it would break the latest-minus-one floor); enforcing the 1 GiB ceiling inside the allocator (a refused allocation in an infallible `Vec` path aborts the process, Go included — the ceiling is enforced at adoption instead) |
| 2026-09-24 | Interop hardening from the allocator audit | A `*Buffer` holds its `*Handle`. The Handle's GC cleanup closes on its own goroutine. A second `Close` waits for the first to finish. `WaitBuffer` carries a small result on 64-byte aligned Go memory when the handle is poisoned. `gusset_submit` validates `(ptr, len)` before it builds a slice. `Handle::close` never joins the thread it is running on. `Handle::open` grows a Linux completion pipe to `8 × pool_size` or refuses to open. Go latches poison on `FFI_POISONED` as well as on panic | Each item is reproduced by a test that fails on the previous code. A reachable Buffer let its handle be collected, and the collected handle freed memory under a live slice. An inline cleanup stalled every other cleanup in the process behind a join. A poisoned sibling lost a finished result of 4 KiB or less. A worker holding the last `Arc` joined itself (EDEADLK), and the pipe never closed. Under `pipe-user-pages-soft` a one-page pipe holds 512 tickets, while a pool can have 1024 workers | A new export for a poison-exempt allocation (it grows the verified 15-export surface for one edge case); clamping the pool size to the pipe's capacity (the caller would silently get a different capacity) |
| 2026-09-24 | Second interop audit | Workers block SIGPIPE in their own signal mask. Undelivered completion tickets are kept and retried. `JobOutput` is `#[non_exhaustive]`. Dependents gate on `DEP_GUSSET_ALLOCATOR_API` (`links = "gusset"`), not a copied probe. Go's caller paths use `TryRLock` on `cgoMu`: only `close` takes it exclusively, so a failed try means "closing" | SIGPIPE on a thread Go did not create is re-raised with the default action and exits the process.
